# MARS-Graph 前端设计方案 v0.1（仅设计，不含代码）

> 对齐基线：`mars/graph/edge_table.py`（12 条边）、`mars/graph/state/schema.py`（11 字段）、
> `mars/runtime/breakpoints.py`（断点载荷/改道校验）、`mars/graph/state/errors.py`（错误码）、
> `mars/runtime/runner.py`（运行状态与 SSE 事件）、`mars/api/app.py`（现有接口）。
> 文中标注 `【Gap】` 者，为「需求要求但当前后端未提供」的能力，见第 3.1 节。

---

## 1. 一句话产品定位

**MARS-Graph 是一个「可介入」的多智能体提示词优化工作台——用一张带断点、可改道、可回放的节点状态图，把 8 节点 / 11 字段的 TSC·M 双层循环，从黑盒跑批变成工程师能停下来看一眼、改一下再走的可控流程。**

---

## 2. 信息架构与导航结构

### 2.1 全局主对象

`Run`（一次运行，`thread_id` = `run-xxxx`）是贯穿全站的主对象。所有页面 URL 均携带 `run_id`，切换页面不丢失运行上下文。

```
Run（run_id）
├── 输入域：任务名 / 1 初始提示词 / 4 优化方向及目的 / 9 性能指标 / TSC_max / M_max
├── 执行域：节点状态 ×8 / 边状态 ×12 / 断点集合 / 人工介入记录
├── 状态域：字段 1–11 / trace / route_* / 报错 issues
└── 产出域：3 已优化提示词 / report_md / 验收结论 / diff
```

### 2.2 导航结构

```
L0  工作台（AppShell：左侧导航 + 顶部全局条 + 抽屉宿主 + 覆盖层）
├── L1 运行控制台        /runs/:runId                       ← 默认落地页（有活动运行且是本会话最近一次）
├── L1 新建任务          /runs/new                          ← 无运行时为默认落地页
├── L1 节点配置          /settings/nodes                    ← 也可在控制台内以抽屉形态打开（只读镜像）
├── L1 历史运行          /runs                              ← 每次运行结束自动成为一条历史记录
└── L1 输出报告          /runs/:runId/report                ← 运行 completed 后可进入；运行中为锁定态
        └── 子视图：最终提示词 / 优化报告 / 初始↔最终 diff

全局覆盖层（不属于导航，任意页面可唤起）
├── 命令面板 ⌘K（跳 run、跳节点、切抽屉 tab、设断点）
├── 断点干预弹窗（阻塞式，禁止 Esc 关闭）
├── 状态与日志抽屉（控制台常驻，报告页以只读抽屉复用）
└── Toast / 全局错误横幅
```

### 2.3 导航高亮与降级规则

| 场景 | 规则 |
| --- | --- |
| 无活动运行 | 左导航只有「新建任务 / 历史运行 / 节点配置」可用，控制台与报告置灰并提示「先创建任务」 |
| 运行中 | 左导航「运行控制台」常亮；「输出报告」加锁图标，hover 提示「运行结束后可查看」 |
| run_id 不存在 / 进程重启后丢失 | 页面进入「运行不存在」态：保留导航、给出 `run_id`、提供「查看历史」「复制参数新建」两个出口，不白屏 |
| 断点命中 | 任何页面顶部出现琥珀色阻塞条「运行已暂停 @ gate:critic→teacher」，点击回到控制台并自动打开干预弹窗 |

## 3. 页面清单及入口关系

| 编号 | 页面/模块 | 形态 | 路由 | 入口 | 前置条件 | 主要出口 |
| --- | --- | --- | --- | --- | --- | --- |
| P0 | AppShell（导航骨架） | 布局 | — | 全局 | — | — |
| P1 | 运行控制台 | 页面 | `/runs/:runId` | 左导航、创建成功后自动跳转、历史「查看」 | 已存在 run_id | 报告页、抽屉、断点弹窗 |
| P2 | 新建/编辑优化任务 | 页面 | `/runs/new`、`/runs/new?from=:runId` | 左导航、空态 CTA、失败报告「复制为新任务」 | 无 | 启动 → P1；存草稿 → 留在本页 |
| P3 | LLM 节点配置 | 页面 + 抽屉 | `/settings/nodes`、`/runs/:runId?panel=config` | 左导航、P2「模型配置」入口、控制台 RunBar「配置」 | 无（配置作用于新运行；运行中为只读快照） | 返回来源页 |

| P7 | 状态与日志抽屉 | 组件 | `/runs/:runId?panel=state\|log\|issue\|llm` | 控制台右侧常驻、节点点击、报错角标 | 存在 run | 节点详情、边详情 |
| P8 | 回放模式 | P1 子模式 | `/runs/:runId?mode=replay&t=:index` | 历史「回放」 | run 已结束且事件序列完整 | 退出回放 → 只读快照 |

### 3.1 与现有后端能力的差异（影响可交付范围）

| # | 需求点 | 现状 | 建议 |
| --- | --- | --- | --- |
| G1 | 页面可配置 TSC/M 上限 | `TSC_MAX=5 / M_MAX=3` 为常量，`POST /runs` 不接收 | 需新增 `tsc_max/m_max` 入参与 `GraphState` 字段（违反「不新增未登记键」，需你确认）；否则 UI 只读展示 `5 / 3` |
| G2 | 历史运行 / 回放 | `RunManager._runs` 与 checkpointer 均为进程内内存，重启即失 | 历史页需落库（run 元数据 + 事件序列 + 终态）；否则只能做「本次会话历史」 |
| G3 | 报告「未达标项与理由」 | `Target` 仅写 `route_target` + 通用 summary，逐项 `criteria` 结论未落状态 | 需在 Target trace 中保留逐项结论（或扩展字段），否则报告页只能显示「未通过」 |
| G4 | 提示词模板正文 | 仅 `mars/prompts/<node>/vN.md` 文件 + 版本号，无读取/编辑接口 | 需新增模板读取（只读预览可先做）；在线编辑另议 |
| G5 | 「暂停」按钮 | 无 pause 接口，只有断点挂起与 abort | 建议「暂停」=「对当前即将经过的边临时置断点」；否则顶部不提供暂停，只提供「设断点」 |
| G6 | 「终止」语义 | `resume(action=abort)` → `goto=END`，不生成 `report_md` | UI 文案必须写「终止 = 立即结束、不生成报告」，避免用户以为有失败报告 |

## 4. 页面八项模板

### P1 运行控制台

**① 页面目标**：在一个屏幕内回答四个问题——现在跑到哪、为什么走这条边、有没有问题、我能不能介入。

**② 入口与前置条件**：左导航 / 创建成功自动跳转 / 历史「查看」；前置：`run_id` 存在。运行中进入为实时态，已结束进入为只读快照态（顶部灰条「已结束 · 只读」）。

**③ 布局结构**
- 顶：`RunBar`（64px）——任务名、`run_id`（可复制）、运行状态胶囊、当前节点、TSC/M 计量条、断点计数、耗时、控制按钮组。
- 左：`SideNav`（200px，可折叠至 48px）。
- 中：`GraphCanvas`（自适应，最小 640×420）——工具条（适配/缩放/自动跟随/图例）、节点-边画布、MiniMap。
- 右：`InspectorDrawer`（360–480px，可拖拽调宽，可全收起）——四个 tab。
- 底：`BottomActionBar`（48px）——当前字段摘要条（2/3 提示词前 80 字）、「复制当前提示词」「导出快照」「查看报告」「断点集合」。

**④ 核心组件清单**

| 组件 | 职责 | 数据来源 |
| --- | --- | --- |
| `RunBar` | 运行级状态与全局控制 | `status`、`next`、`tsc_count`、`m_count`、断点集合 |
| `RunStatusPill` | 运行状态（6 值） | `status` + 是否 `interrupts` 非空 |
| `CounterMeter` | TSC x/y、M x/y，超限变色 | 10/11 + 上限 |
| `GraphCanvas` | 图渲染与交互 | 边表 + 节点状态派生 |
| `NodeCard` | 节点名/状态/摘要/耗时/报错码/执行次数 | `trace` 聚合 |
| `EdgeLayer` | 普通实线、条件虚线 + 条件标签 + 副作用标记 + 断点图标 | 边表 + 路由键 |
| `InspectorDrawer` | 四 tab 宿主 | 快照 + 事件流 |
| `BottomActionBar` | 轻量高频动作 | 2/3/报告 |

**⑤ 交互行为**
- 运行中：SSE 事件驱动增量刷新（`node_start` / `node_end` / `node_error` / `breakpoint` / `run_completed` / `run_failed`）；`自动跟随` 开启时视口平移至当前节点。
- 点击节点 → 抽屉切「节点详情」：输入摘要、输出摘要、`writes`、`side_effects`、`issues`、`summary`（路由原因）、`model`、`prompt_version`、`duration_ms`、执行次数与历次记录。
- 点击边 → 就近浮层：`edge_id`、`source→target`、`kind`、`condition`、`side_effects`、`[设断点/取消断点]`；条件边额外显示「本次路由判定依据」。
- 画布：滚轮缩放（0.5–2.0）、拖拽平移、`F` 适配、双击节点聚焦、`Esc` 取消选择。
- 控制按钮：运行中 `暂停(G5)/终止`；`paused` 时 `继续`（等价「继续原路由」）；终止需二次确认并说明不产报告。

**⑥ 展示的数据字段**

| 区域 | 字段 |
| --- | --- |
| RunBar | 运行状态、当前节点、**10**/**11** 及上限、断点集合、`run_id`、耗时 |
| 节点卡 | 节点状态、`trace.summary` 截断 40 字、`duration_ms`、`issues[0].code`、执行次数 `×n` |
| 边 | 普通/条件、条件文本、`side_effects`、已走/未走/断点 |
| 抽屉-状态字段 | **1–11** 全量 |
| 抽屉-日志 | 事件时间线 + `trace` |
| 抽屉-报错 | `issues`（`E1-*` 红 / `E2-*` 黄） |
| 底部条 | **2** / **3** 摘要、**5**/**6** 计数（`pending 2 · open 3`） |

**⑦ 状态与异常**

| 场景 | 表现 |
| --- | --- |
| 加载 | 骨架屏：画布保留布局框架 + 节点灰卡；RunBar 显示 `—`，禁止操作 |
| 空（新建未启动） | 画布全灰「待运行」，中置 CTA「启动运行」 |
| 运行中 | 当前节点脉冲描边，已走边高亮，事件流滚动，RunBar 蓝色胶囊 |
| 暂停（断点） | 断点边红色脉冲 + 全屏 2px 琥珀边、RunBar 紫色 `已暂停`、自动打开 P4 |
| 2 级警告 | 节点卡右上 `W` 琥珀角标 + RunBar `警告 n` 计数；不弹窗 |
| 1 级报错 | 红色横幅置顶「E1-MISSING-OPTIMIZED-PROMPT @ critic」、图冻结、按钮仅剩「导出快照/查看报错/复制为新任务」 |
| 超限 | TSC 达上限：`CounterMeter` 变琥珀 + 标注「TSC 超限 → 强制 Target」；M 达上限：红色 + 「强制 Output，生成失败报告」 |
| 失败（网络/404） | 断流 → 顶部黄条「事件流已断开，正在重连（3s）」指数退避；404 → 空态页 |

**⑧ 验收标准**
- [ ] 单屏内可同时看到：运行状态、当前节点、TSC/M、节点/边状态、最近一条报错摘要。
- [ ] 节点与边的每一次状态变化都能对应到一条可展开的事件/`trace`。
- [ ] 断点命中后 1s 内出现阻塞弹窗，且未决策前图与控制按钮全部禁用。
- [ ] 1 级报错后不存在任何「继续」入口。
- [ ] 1440×900 与 1280×800 下不出现横向滚动；1920 宽下画布不空旷。

### P2 新建/编辑优化任务

**① 页面目标**：在 90 秒内完成一份可启动的运行配置，并在启动前把「必然失败」的原因挡掉。

**② 入口与前置条件**：左导航「新建任务」、空态 CTA、历史「复制为新任务」（`?from=` 预填 1/4/9）、失败报告「调整后重跑」。前置：无。带 `?from` 时标题为「编辑任务（基于 run-xxxx）」。

**③ 布局结构**
- 顶：页头（标题 + 草稿保存态「已保存 14:02」+ 主按钮组）。
- 中：单列 720–840px 表单，分 4 个区块（① 任务基本信息 ② 提示词 ③ 验收指标 ④ 循环与模型）。
- 右：`校验面板`（sticky，320px）——实时列出阻断项/警告项、本次将使用的节点模型快照。
- 底：固定操作条——`保存草稿` `启动运行`（主）+ 快捷键提示 `⌘↵`。

**④ 核心组件清单**：`TaskMetaForm`、`PromptEditor`（CodeMirror 风格，行号、字数、`{{}}` 变量高亮）、`GoalEditor`、`CriteriaTable`（name/threshold/comparator 增删行）、`LoopLimitField`、`NodeConfigSummary`（6 节点模型名 + 配置入口）、`ValidationPanel`、`DraftStateBadge`。

**⑤ 交互行为**
- 校验：字段级即时校验（失焦）+ 提交级汇总校验；阻断项存在时 `启动运行` 置灰并显示原因。
- 性能指标：至少 1 条；`comparator` 三选一（`≥ gte` / `≤ lte` / `= eq`）；`name` 重复给警告不阻断。
- 循环上限：若 G1 未确认，显示只读 `TSC 5 / M 3` 并挂 `info`「当前版本固定，如需可配需后端支持」。
- 草稿：本地草稿自动保存（800ms 防抖），离开页面有未启动修改时二次确认。
- 启动：`POST /runs` → 202 返回 `thread_id` → 跳转 P1，Toast「run-0007 已启动」，并把当前断点预选集带入。

**⑥ 展示的数据字段**：写入 **1、4、9**；读取并展示 **TSC_max / M_max**；不展示 2/3/5/6/7/8/10/11（运行产物）。模型配置只展示 `model`、`base_url` 域名、`api_key_env` 名称，不展示任何密钥。

**⑦ 状态与异常**

| 场景 | 表现 |
| --- | --- |
| 加载 | 表单骨架 + 校验面板骨架 |
| 空（首次） | 三块空输入 + 内联示例（「把散乱的客服话术整理为结构化 SOP」）可一键填入 |
| 校验失败 | `初始提示词不能为空`（阻断）、`性能指标至少 1 条`（阻断）、`指标名重复`（警告） |
| 2 级 | 黄条「未配置 Model 的节点将使用全局默认」，允许启动 |
| 1 级 | 红条「6 个 LLM 节点中有 2 个缺少可用 API Key 环境变量」，禁止启动，附「去节点配置」 |
| 草稿恢复 | 顶部条「发现上次未提交的草稿（14:02）· 恢复 / 丢弃」 |

**⑧ 验收标准**
- [ ] 任一阻断项都能定位到具体控件并自动滚动聚焦。
- [ ] 启动后 1 次点击即可回到控制台并看到 `run_started` 事件。
- [ ] 启动请求失败（400/网络）时表单内容不丢失，错误可复制。
- [ ] 性能指标支持 0–N 条增删，删除后无残留校验。

### P3 LLM 节点配置（页面 / 抽屉）

**① 页面目标**：以最小认知成本把 6 个 LLM 节点接到可用模型上，并将「改了哪个、影响谁、怎么回退」讲清楚。

**② 入口与前置条件**：左导航「节点配置」；P2「模型配置」；控制台 RunBar「配置」（抽屉形态）。前置：无。**运行中使用的是启动时的配置快照，运行中修改只影响后续新建运行**——此点必须在页面顶部常驻说明。

**③ 布局结构**
- 左：节点列表（Planner / Teacher / Student / Critic / Target / Manager），带状态点（已配置/使用默认/异常）。
- 中：配置表单（分组：连接 / 采样 / 可靠性 / 提示词模板）。
- 右：`生效范围与差异`（当前值 vs 默认值 vs 环境变量来源）。

**④ 核心组件清单**：`NodeList`、`NodeConfigForm`、`SecretField`、`TemperatureSlider`、`RetryStepper`、`PromptVersionSelect`、`PromptPreviewPane`、`ResetConfirmDialog`、`ConfigDiffBadge`。

**⑤ 交互行为**
- 字段：`model`、`base_url`、`api_key_env`（**环境变量名**，非密钥本体）、`temperature` 0–2 步进 0.1、`timeout_s` > 0、`max_retries` 0–10、`prompt_version`（`^v\d+$`）。
- 保存：局部 `PATCH /config/nodes/{node}`，仅提交变更字段；成功后就地显示「已生效（新运行）」。
- 恢复默认：`DELETE`，二次确认弹窗列出将被清空的覆盖项。
- 版本与恢复默认：`prompt_version` 变更前先校验存在性（失败给「模板 v3 不存在」），并展示模板正文预览【Gap G4：无正文接口时降级为仅版本号】。
- API Key：输入框 `type=password`，粘贴即掩码，失焦不回显；保存后仅显示 `env: MARS_LLM_API_KEY` 与末 4 位（若后端提供指纹）【Gap】。

**⑥ 展示的数据字段**：`model`、`base_url`（只显示 host，避免泄露内网路径）、`api_key_env`、`temperature`、`timeout_s`、`max_retries`、`prompt_version`。不涉及 1–11。

**⑦ 状态与异常**

| 场景 | 表现 |
| --- | --- |
| 加载 | 列表 + 表单骨架 |
| 空（未配置节点） | 「使用全局默认」徽标 + 一键「复制全局默认」 |
| 保存中 | 按钮 loading，表单锁定 |
| 2 级 | 「该节点将回退到全局默认模型」黄条，可保存 |
| 1 级 | 「base_url 非法 / model 为空」红条，禁止保存 |

| 模板不存在 | 版本下拉标红 + `v3 不存在`，回退到上一个合法值 |

**⑧ 验收标准**
- [ ] 任何位置都不出现明文 Key，网络面板与日志中同样不出现。
- [ ] 页面内可完整回答「这个节点现在用什么模型、从哪来、改过没有」。
- [ ] 恢复默认有二次确认且可撤销（提示需重新保存）。

### P4 断点干预弹窗

**① 页面目标**：在「状态已冻结、下一节点未执行」的瞬间，用一屏信息支撑「继续 / 改道 / 终止」三种决策，并让后果完全可预期。

**② 入口与前置条件**：SSE `breakpoint` 事件、刷新后快照 `interrupts` 非空、深链 `?interrupt=`、琥珀阻塞条。前置：`status=paused` 且存在中断载荷（`edge_id`、`state_digest`、`route`、`allowed_reroutes`、`counters`）。

**③ 布局结构**：80% 宽模态（最大 1080px），三栏式——
- 左（360）：边信息 + 命中快照摘要（`state_digest` 前 12 位、`route`、`counters`）。
- 中（flex）：状态快照（**1–11**，与上一节点执行前的 diff 高亮）+ 「本次已发生的副作用」。
- 右（320）：决策区——继续原路由 / 强制改道（目标选择器）/ 终止；底部常驻不变量说明。

**④ 核心组件清单**：`HitBanner`、`EdgeIdentityCard`、`SnapshotDiffTable`、`SideEffectList`、`RerouteTargetPicker`、`InvariantNotice`、`SupplementEditor`（仅 target=user）、`AbortConfirm`、`DecisionFooter`。

**⑤ 交互行为**
- 「继续原路由」：展示目标节点与将发生的副作用（若有 10/11 递增，明确标注「将保留本次 +1」）。
- 「强制改道」：目标选择器只列出 `allowed_reroutes`；不在列表内的节点置灰并给出原因（例如 `output` 需 3 非空）。选择后即时提示「将对目标节点做必要输入校验」。
- 目标含 `user` 时，展开 `SupplementEditor`：补充 1 / 4，模式 `追加 append` / `替换 replace`。
- 「终止」：二次确认，文案「立即结束，不生成报告；已产生的快照仍可导出」。
- 提交：`POST /runs/{id}/resume`，按钮 loading 期间弹窗不可关闭；成功后关闭并刷新图。
- 失败：改道被拒（`E2-REROUTE-REJECTED`）时弹窗**不关闭**，就地琥珀提示「改道被拒绝：目标节点必要输入校验未通过（E2-SCHEMA-…），已按原路由继续」，并给「查看校验详情」。
- 键盘：`Enter` 继续（需焦点在按钮）、`Esc` 无效（防误关）。

**⑥ 展示的数据字段**：边 `edge_id/source/target/kind/condition/side_effects`；快照 **1–11** 全量；`counters` = **10/11**；`route` 原路由；`allowed_reroutes`。

**⑦ 状态与异常**

| 场景 | 表现 |
| --- | --- |
| 加载 | 弹窗骨架 + 「正在读取快照…」 |
| 空（无中断） | 不渲染；若由深链强制打开 → 关闭并 Toast「当前无待处理断点」 |
| 提交中 | 全弹窗 loading，禁止改选 |
| 2 级（改道被拒/载荷非法） | 琥珀内联提示 + 保持弹窗；运行按原路由继续 |
| 1 级（快照不可用/run 已失败） | 红色态：「运行已终止，无法继续」，仅留「导出快照」 |
| 会话失效（404） | 「该运行已不存在」，仅留「返回历史」 |

**⑧ 验收标准**
- [ ] 弹窗内可完整回答：命中哪条边、原路由去哪、还能去哪、继续或改道后计数怎么变。
- [ ] 不选目标时「强制改道」不可提交；选到非法目标有明确原因。
- [ ] 决策提交后必须出现一条人工介入记录（`gate:<edge_id>`、原路由、新路由、操作人、时间）。
- [ ] 任何操作都不会关闭弹窗而让运行处于「无人决策的 paused」超过 30s 无提示。

### P5 输出报告页

**① 页面目标**：即使失败，也能让用户在一屏内拿到「结论 + 理由 + 最终提示词 + 可复制产出」。

**② 入口与前置条件**：左导航、RunBar「报告」、完成 Toast、历史「验收结论」。前置：`status=completed`；运行中打开为锁定预览（骨架 + 「运行结束后解锁」）。`failed`（1 级报错 / abort）不进入本页，改走独立「终止现场」视图。

**③ 布局结构**
- 顶：`VerdictCard`（结论 + TSC/M + 时间 + `run_id` + 状态徽标）。
- 中左（主）：`FinalPromptBlock`（代码块，行号、换行开关、字号、复制、下载 `.md`/`.txt`）。
- 中右（380）：`AcceptancePanel`（逐项指标：达标/未达标/无结论 + 理由）→【Gap G3】无逐项数据时显示「未返回逐项结论」+ Target 摘要。
- 下：`ReportMarkdown`（`report_md` 渲染，可折叠章节）+ `PromptDiff`（1 ↔ 3，unified / side-by-side 切换）+ `SubtaskQuestionTables`（5/6 状态全量，含 dropped）。
- 底：`导出` `复制最终提示词` `复制为新任务` `回到控制台`。

**④ 核心组件清单**：`VerdictCard`、`FinalPromptBlock`、`CopyDownloadBar`、`AcceptancePanel`、`CriterionRow`、`ReportMarkdown`、`PromptDiff`、`UnmetReasonList`、`ReplayLink`。

**⑤ 交互行为**
- 复制：优先 `navigator.clipboard`，失败降级选中文本 + 提示。
- 下载：`.md`（含报告全文）、`.txt`（仅最终提示词）。
- diff：默认 unified，可切 side-by-side；超长提示词按段落折叠，首屏只展开差异块。
- 「复制为新任务」：跳 P2 并预填 1（当前 3 作为新的初始提示词）/4/9，并标记「来源 run-xxxx」。
- `report_md` 渲染：禁用原始 HTML，代码块强制等宽，表格横向可滚动。

**⑥ 展示的数据字段**：**3**（最终提示词）、**1**（diff 左侧）、**4**、**5**/**6** 全量状态、**7**/**8**（分数+维度+summary）、**9**（逐项对比）、**10**/**11**、`report_md`、验收结论、`route_target` / `route_manager`。

**⑦ 状态与异常**

| 场景 | 表现 |
| --- | --- |
| 加载 | 骨架（结论卡 + 代码块占位） |
| 空（3 为空） | 红色「未产出最终提示词」，隐藏复制/下载，保留报告与 diff 说明 |
| 成功模板 | 绿色结论卡「通过验收」+ 达标项全绿 + 最终提示词主位 |
| 失败模板（验收不通过） | 琥珀结论卡「未通过验收 · 进入 Manager 回退」+ 未达标项逐条 + 最终提示词**仍完整展示** |
| 失败模板（M 超限） | 红色结论卡「M 超限 · 强制输出」+ 标注「未回退，结果为当前最优」 |
| 2 级警告 | 结论卡下方黄条「本次运行含 3 条警告，可能影响结论可信度」+ 展开列表 |
| 1 级 / abort | 不进本页；展示「终止现场」：原因、最后节点、字段快照、导出 |

**⑧ 验收标准**
- [ ] 首屏 3 秒内可读到：结论、TSC/M、最终提示词首行。
- [ ] 失败态下最终提示词、未达标理由、报告三者都可见，无任何「隐藏失败信息」的处理。
- [ ] 复制/下载内容与页面展示逐字一致（含空行与缩进）。
- [ ] `dropped` 项在 5/6 表格中以删除线 + `dropped` 标签保留可见。

### P6 历史运行

**① 页面目标**：快速回答「上次为什么没过、参数差在哪、能不能直接复跑」。

### P7 状态与日志抽屉

**① 页面目标**：作为控制台的「事实层」——任何图上的颜色都能在这里找到文字依据。

**② 入口与前置条件**：控制台右侧常驻；节点点击（切到节点详情）；报错角标（切到报错列表）；RunBar 计数点击（切到对应 tab）。前置：有 run 快照。

**③ 布局结构**：顶部 tab（`状态字段` / `运行日志` / `报错 n` / `LLM 调用 n`）→ 过滤/搜索条 → 滚动内容区 → 底部「复制为 JSON」。

**④ 核心组件清单**：`DrawerTabs`、`FieldRow`（编号徽标 + 名称 + 值 + 读写标记）、`ListFieldGroup`（5/6 项级状态）、`ScoreField`（7/8：分 + 维度条 + summary + evidence）、`CounterField`（10/11：`x / max` + 进度）、`NodeDetailPanel`、`LogFilterBar`、`LogRow`（可展开原始 JSON）、`IssueList`、`LLMCallTable`。

**⑤ 交互行为**
- 字段行：只读字段显示 `只读` 徽标与写入者（如 `由 critic 写`）；悬停显示「上次变更节点 + 时间」。
- 5/6 列表：默认隐藏 `dropped`，可切「显示全部」；每项显示 `id / content / score / status`；支持按状态筛选；不提供删除按钮。
- 日志：级别/节点/关键字筛选，时间倒序，支持「跟随最新」开关；单条可复制、可展开 payload。
- LLM 调用：`node / model / prompt_version / duration / retries / 结果状态`，失败行高亮并可展开错误。
- 复制为 JSON：复制当前 tab 的可见数据（脱敏后，不含任何密钥）。

**⑥ 展示的数据字段**：**1–11** 全量 + `trace` + `issues` + 路由键；不展示模型密钥。

**⑦ 状态与异常**

**派生规则（前端唯一事实来源）**
- `nodeStatus` = `trace` 中该节点最近一次记录 + 是否有 `node_start` 未配对：`running` > `error(issues.level=1)` > `warn(issues.level=2 且完成)` > `success` > `idle`；被改道绕过 → `skipped`。
- `edgeStatus` = `pending | traversed | taken(条件命中) | not-taken(条件未命中) | armed(已设断点) | hit(命中暂停) | overridden(人工改道)`。

### 7.5 1 级报错与 2 级报错的处理差异

| 维度 | 1 级（红） | 2 级（黄） |
| --- | --- | --- |
| 运行 | 立即终止，图不再推进 | 继续执行 |
| 页面 | 顶部红色横幅（节点 + `code` + 字段 + 时间），画布冻结为「现场」，右侧抽屉自动切报错 tab | 顶部计数 + 内联角标，页面可正常操作 |
| 可执行动作 | 复制报错、导出快照、查看已完成节点、复制为新任务 | 继续、设断点、查看详情 |
| 禁止动作 | 继续 / 改道 / 重试该节点 | 无（但提供「查看影响」提示） |
| 数据 | 保留最后一次成功状态与失败节点 `trace` | 保留 issue 明细，可折叠 |

### 7.6 API Key 脱敏规则

1. 输入框 `type=password`，`autocomplete=off`，粘贴后立即以 `••••` 呈现，**失焦不回显**。
2. 保存成功后仅显示：`env: MARS_LLM_API_KEY`（变量名）+（若后端提供指纹）`末 4 位 ····9f3a`。
3. 页面任何位置（含 tooltip、报错文案、复制 JSON、日志、LLM 调用记录、导出报告）**永不出现明文**。
4. 网络层：请求体只提交 `api_key_env`；若未来支持直接录入，则提交后立即从内存表单状态清除。
5. 复制按钮对密钥字段禁用；浏览器 DevTools 提示不构成合规理由。
6. 校验失败提示只说「环境变量未解析」，不回显值。

### 7.7 断点改道的固定提示文案（常驻，不只 Toast）

> **改道只改变下一个执行节点，不改变流程事实：**
> ① 目标节点**照常执行必要输入校验**，校验不通过将拒绝改道并**按原路由继续**（`E2-REROUTE-REJECTED`）；
> ② **不改变 10/11 计数**，本次已发生的 TSC/M 递增与边副作用（如 `2←3`、`3 置空`）**保留且不可回滚**；
> ③ 本次操作写入人工介入记录：`gate:<edge_id>` · 原路由 → 新路由 · 操作人 · 时间。

## 8. 断点干预完整交互流程

### 8.1 状态机

```
[未设断点] --点击边/断点面板--> [已设 armed]
[已设 armed] --运行经过该边 gate--> [命中 hit] --事件 breakpoint--> [UI 暂停 paused]
[命中 hit] --继续--> [resumed: 原路由] --gate 执行--> [下一节点]
[命中 hit] --改道(合法)--> [resumed: 新路由] --gate 执行--> [目标节点]
[命中 hit] --改道(非法)--> [拒绝: E2-REROUTE-REJECTED] --> [按原路由继续] (仍为 level 2)
[命中 hit] --终止--> [abort → END] --> [status=completed, 无 report_md]
[已设 armed] --再次点击/断点面板取消--> [未设断点]
```

### 8.2 端到端流程

1. **设断点**：用户在画布点边或左导航断点面板勾选 → `POST /runs/{id}/breakpoints`（全量替换 `edge_ids`）→ 边显示 `⛔ 空心` → Toast「已设 2 个断点」。
2. **命中**：源节点完成状态更新（含边副作用）后进入 `gate`，命中即 `interrupt`，推送 `breakpoint` 事件，载荷：`edge_id`、`state_digest`、`route`、`allowed_reroutes`、`counters{tsc_count,m_count}`。
3. **暂停**：`status=paused`；UI 全屏琥珀描边 + RunBar 紫色 + 自动打开 P4；画布与按钮锁定。
4. **阅读**：弹窗展示边身份、原路由、`allowed_reroutes`、**1–11** 与「本次已发生副作用」，`state_digest` 前 12 位用于与历史记录比对。
5. **决策**
   - **继续原路由** → `{action:"continue"}`；提示「将保留本次 10/11 递增」。
   - **强制改道** → 选择目标（仅 `allowed_reroutes`）→ `{action:"reroute", target}`。
     - 前端先用同一套契约做**预校验**（目标必要字段齐全、`output` 需 3 非空），不通过的选项直接禁用并给原因，减少后端拒绝。
     - 若目标为 `user`，展开补充编辑器（1 / 4，`append|replace`），随 `resume` 一并提交。
   - **终止** → 二次确认 → `{action:"abort"}` → `goto=END` → 运行结束但**无报告**，进入「终止现场」页。
6. **提交**：`POST /runs/{id}/resume` → 按钮 loading，弹窗不可关闭、不可 Esc。
7. **结果**
   - 成功：关闭弹窗 → 图更新（被改道边标橙、跳过的节点变 `⊘`）→ 抽屉新增一条人工介入记录 → Toast「已改道至 target」。
   - 被拒：弹窗保持，内联琥珀「校验未通过（`E2-SCHEMA-*`），已按原路由继续」+「查看详情」跳报错 tab；用户可重新决策或关闭。
   - 异常：404 → 「运行已不存在」；网络失败 → 保持弹窗 + 重试按钮（幂等由后端 `status != paused` 校验兜底）。
8. **留痕**：每次决策生成一条 `gate:<edge_id>` 的 trace（`human_intervention=true`、`original_route`、`new_route`、`operator`、`at`），在日志与边详情中永久可查。

### 8.3 不变量（UI 必须显式承诺）

| 不变量 | UI 表达 |
| --- | --- |
| 不跳过目标节点必要输入校验 | 目标选择器下方常驻说明 + 预校验结果标签 |
| 不改变 10/11 计数 | 决策区展示「当前 TSC 2/5 · M 1/3 → 决策后不变」，与「边副作用已 +1」分两行说明 |
| 副作用不可回滚 | 「本次已发生副作用」区块用琥珀底标注「已生效，改道不会撤销」 |
| 决策可追溯 | 提交后 Toast + 日志中可见操作人/时间/原路由→新路由 |

### 9.2 通用呈现规则

1. **两级三处**：级别同时出现在「顶部横幅（全局）/ 节点卡（局部）/ 抽屉列表（明细）」，三处可互相跳转。
2. **颜色 + 图标 + 文字**三重编码：红=终止、琥珀=警告、蓝=进行、绿=成功、紫=暂停、灰=跳过/空。
3. **错误码可复制**：所有 `code` 支持一键复制，便于贴进 issue。
4. **不吞信息**：失败态必须保留 `3 已优化提示词`、`report_md`、未达标理由与全部 `issues`。
5. **1 级终止后的现场保留**：画布冻结在最后状态（含当前节点红卡），RunBar 只剩「导出快照 / 复制为新任务 / 查看报错」，刷新页面仍可复原（依赖后端快照）。
6. **事件流断连**：顶部黄条「事件流已断开，重连中（第 n 次）」；重连后按 `start_index` 回放，不重复渲染；超过 5 次失败降级为 5s 轮询快照。
7. **长时运行**：单节点超过 `timeout_s × 1.5` 未回事件 → 节点卡显示「疑似超时（已 92s）」，不自动终止。

## 10. 需要你确认的 5 个关键问题

**Q1（必须）断点对象与语义到底绑定在哪一层？**
现状：断点是**边级**且挂在 `gate`（源节点更新之后、目标节点之前），12 条边全部可断；改道候选 = 源节点候选 ∪ `{user, planner, teacher, manager, target}`，`output` 仅在 3 非空时可选；改道被拒只记 2 级并**按原路由继续**。
需要你确认：
- 断点是否允许「节点级」（进入前 / 离开后），还是永远「边级 gate」？
- 条件边与普通边是否统一语义（都停在同一时机）？
- 改道是否允许**回滚已发生的边副作用**（如 `critic→teacher` 已执行 `2←3`、`10+1` 后又改道 Target，TSC 已被消耗）？当前实现是**不可回滚**——这会直接改变干预弹窗的文案与「继续/改道」的默认推荐。

**Q2 TSC_max / M_max 是否真的需要每任务可配？**
现状为常量 5 / 3，`POST /runs` 不接收，且 `GraphState` 不允许新增未登记键。若必须可配，需要新增 2 个状态字段并贯穿 Manager/Critic/Output 报告；若不需，UI 将显示只读 `5 / 3`（并去掉 P2 的配置项）。

**Q3 历史运行与回放要做到什么持久化程度？**
现状全部在进程内存，重启即失。请确认：跨会话历史 + 事件级回放（需要落库 run 元数据与事件序列）／仅本次会话（轻量，但刷新即失）／仅存终态快照（可看报告，不可回放）。

**Q4 「未达标项与理由」的数据从哪来？**
现状 `Target` 只把逐项 `criteria` 结论写入 LLM 响应后丢弃，状态里只有 `route_target` 与通用 summary，因此报告页**无法**逐项说明「哪条指标没达到、为什么」。是否允许扩展（写进 trace 结构化字段 / 新增状态键 / 由 Output 重新生成一次验收叙述）？

**Q5 API Key 与提示词模板的编辑边界在哪？**
现状后端只保存 `api_key_env`（环境变量名），不存密钥、无尾号；提示词只有 `mars/prompts/<node>/vN.md` 文件与版本号，无正文读写接口。请确认：前端是否允许录入密钥（录入后存哪、如何算尾号、是否合规）？模板是否允许在线编辑并生成新版本 `vN`，还是只做「选版本 + 恢复默认 + 只读预览」？

### 11.5 条件性待选校验（v0.3 修正）

文档把所有 2 级报错都视为「黄色警告」，但早期实现把**所有**待选字段的缺失都报成 2 级，
且对每个节点都套用「10/11 非 0 → 3/5/6/7/8 必须存在」的全局规则。
实际运行中 Planner 首轮必然没有 3/5，Teacher 首轮必然没有 6/7/8，Critic 首轮必然没有 7/8，
Critic 进入 TSC 又会按设计把 3 置空——一次健康运行会产生十余条 `E2-MISSING-*` /
`E2-SCHEMA-OPTIMIZED-PROMPT`，节点状态图因此失去信号价值。

现在按核心文档的**逐节点前提**收口校验（`mars/graph/contract.py` + `state/validate.py`）：

| 节点 | 待选字段 | 触发前提 |
| --- | --- | --- |
| User | 1 / 4（缺失或空白） | 由 Manager 回退唤醒（`m_count > 0`） |
| Planner | 3 / 5 | TSC 进行中（`tsc_count > 0`） |
| Teacher | 1 / 4 | 由 Manager 唤醒 |
| Teacher | 3 / 6 / 7 / 8 | TSC 进行中 |
| Student | 5 | 无（Teacher 已保证存在） |
| Critic | 2 / 7 / 8 | TSC 第二轮起 |

M 回退会重置 `tsc_count` 并清空上游产物，属于文档定义的正常复位，不计为缺失。
2/3 在循环/回退阶段被置空（`tsc_count > 0` 或 `m_count > 0`）也不再判格式错误。

验收：正常路径、TSC 超限路径与 Manager 回退路径的 trace 均应为 **0 条 issues**，
由 `mars/tests/graph/test_graph.py` 直接断言。前端仍保留「常规缺失」灰色分类，
仅用于兼容历史数据或人工导入的异常状态；其余 2 级（`E2-LLM-*`、`E2-REROUTE-*`、
`E2-TARGET-*` 等）仍为黄色警告，1 级报错不受影响。

### 11.6 断点改道的前端预校验（新增）

后端会拒绝不满足目标契约的改道（`E2-REROUTE-REJECTED`，2 级，按原路由继续）。
实测在 `critic->teacher` 命中时，字段 3 已被置空，此时改道 Target/Manager 必然被拒。
因此弹窗在下拉框层面对每个目标做**必需字段检查**，缺失时直接禁用并显示「缺少已优化提示词」，
避免「看起来可选、提交却被拒绝」。这是设计稿 8.2「前端预校验」的具体实现。

### 11.8 密钥与提示词写入（v0.2 新增）

Q5「API Key 与提示词模板的编辑边界」原结论是「只存环境变量名、模板只读」，v0.2 起改为可写：

| 能力 | 实现 | 安全边界 |
| --- | --- | --- |
| 录入密钥 | `PUT /config/secrets/{env_name}`，写入进程环境变量 + `.mars/secrets.json` | 响应只含 `configured`/`tail`/`source`；明文永不回传，日志不记录 |
| 密钥状态 | `GET /config/secrets` | 只返回尾号与引用节点，页面显示「已配置 ····9876」 |
| 清除密钥 | `DELETE /config/secrets/{env_name}` | 同时弹出进程环境变量并删除文件记录 |
| 连通性测试 | `POST /config/nodes/{node}/test` | 单条 `ping` 请求，返回 ok/耗时/错误摘要 |
| 提示词编辑 | `GET/PUT/DELETE /config/nodes/{node}/prompt` | 版本号正则校验、路径拼接受限、写入后 `load_prompt.cache_clear()` |
| 版本保护 | 删除时校验 | 至少保留一个版本；正在被节点使用的版本不可删除 |
| 推荐模板 | `mars/llm/defaults.py` + 「载入推荐模板」 | 只填入编辑器，不自动落盘，避免覆盖用户已有内容 |

存储位置：未设置 `MARS_HOME` 时为 `./.mars/secrets.json`，设置后为 `<MARS_HOME>/secrets.json`；
权限尽力设为 0600，已加入 `.gitignore`。
优先级：进程环境变量 > 本地文件（`os.environ.setdefault`，显式 `export` 不会被覆盖）。

前端交互要点：
- 密钥输入框为 `type=password`，保存后清空内存值，只回显尾号；不提供「显示明文」。
- 提示词编辑器为等宽字体文本域，显示行数/字符数与落盘路径，未保存时标「未保存」。
- 「新建版本」创建 `vN+1` 并切换编辑目标，但需要「保存配置」才会让节点真正使用新版本——
  两个动作分开，避免误把草稿版本应用到运行。

### 11.9 运行数据持久化与删除（新增）

- 数据目录：`data/runs/<run_id>/`，默认可由 `MARS_DATA_DIR` 覆盖。
- 文件：`meta.json`、`run.log`、`state.json`、`report.md`、`output_prompt.txt`，失败运行额外写 `error.json`。
- `run.log` 为逐行 JSON 事件，写入时剔除完整提示词与报告正文。
- 历史列表合并内存运行与磁盘运行；内存缺失时 `GET /runs/{id}` 回退 `state.json`，因此报告页/控制台在重启后仍可打开已完成记录。
- 历史页新增「日志」弹窗与「删除数据」按钮；运行中/暂停中禁止删除，进程重启遗留的未结束记录按「进程重启中断」展示并允许清理。
- 删除会移除整个子文件夹；前端确认文案显示实际数据路径。
